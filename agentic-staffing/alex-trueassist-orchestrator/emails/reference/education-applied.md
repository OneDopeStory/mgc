# How the education CSV is applied

Source: email-education-source.csv, provided by Mark Cartwright. It is reference material, not a source of customer facts or platform guarantees.

| Source concept | MGC application |
|---|---|
| Chat | Alex accepts a short drafting request and clarifies missing facts |
| Skills and saved prompts | Each staff folder owns reusable email templates; approved refinements update versions |
| Folders and one agent / ICM | Alex routes through roles.json, staff READMEs, and this shared instruction file |
| The desk concept | Load only the current engagement, template, and facts |
| Every prompt word implies choices | Define audience, sender, tone, source facts, next action, and review state explicitly |
| 60–30–10 | Prioritize understanding and verified data; reuse tools; write copy last. This is a working heuristic, not a measured staffing ratio |
| Human review and stages | Editable local draft, optional Gmail draft, content-bound review, then authorized send |
| Deterministic code vs. AI | Validate IDs, required fields, amounts, and duplicates with code during integration; use AI for wording |
| Workspace maintenance | Preserve originals, version approved templates, archive finished work privately, keep maps current |

NotebookLM can help retrieve approved education and company background. Current CRM/accounting/project records remain authoritative for live facts. Upload only sources approved for that knowledge base.
